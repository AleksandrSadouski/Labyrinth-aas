# Labyrinth-aas

Labyrinth-aas — это проект из серии работ '-aas', где игроки соревнуются в прохождении процедурно-генерируемого лабиринта. Каждый игрок управляет своим персонажем, перемещаясь по клеткам лабиринта в поисках выхода. Побеждает тот, кто первым достигнет выхода, но если первый игрок уже финишировал, второй получает шанс на ничью. Игроки могут создавать приватные комнаты по коду, публиковать их на доске объявлений, использовать автоматический подбор соперника в публичных комнатах или играть в одиночном режиме. Ведётся раздельная статистика для PvP (рейтинг Эло, победы, поражения, ничьи, история матчей) и одиночного режима (рейтинг Садовского, счётчик пройденных лабиринтов). Профили других игроков доступны для просмотра. Синхронизация происходит через polling. Это вторая версия проекта, написанная на Laravel.

## Система профиля

Каждый игрок имеет собственный профиль, который хранит имя, пароль, рейтинг Садовского и Эло и полную статистику: количество сыгранных игр, побед, поражений и ничьих в PvP режиме, а также количество пройденных лабиринтов в одиночном режиме. В профиле можно сменить имя или пароль (с подтверждением старого), удалить аккаунт или выйти из системы. При удалении или выходе система проверяет, находится ли игрок в активной комнате, и блокирует операцию, чтобы избежать потери данных или некорректного завершения матча.

В профиле также доступна детальная история всех сыгранных матчей: результат, имя соперника, его рейтинг и собственный рейтинг после каждой игры. Это позволяет отслеживать прогресс и анализировать свои результаты. При желании игрок может полностью сбросить статистику и историю, тогда рейтинг вернётся к базовому значению 150, все показатели обнулятся и история матчей будет удалена. Сброс требует подтверждения паролем и недоступен, если игрок находится в активной комнате.

Любой пользователь может посмотреть профиль другого игрока по его имени — это удобно для оценки уровня соперника перед матчем или после встречи, а также позволяет узнать больше информации о игроках, попавших в таблицу лидеров.

## Игровой процесс

### Геймплей

Игровой процесс строится вокруг пошагового перемещения по процедурно-генерируемому лабиринту. За один ход разрешается переместиться только на соседнюю клетку: вверх, вниз, влево или вправо. Проходить сквозь стены нельзя, поэтому каждый шаг требует внимательности и расчёта. Цель одна: добраться до выхода из лабиринта.

### Локальный PvP

Режим для игры с друзьями. Один игрок создаёт комнату, после чего получает шестизначный код, которым может поделиться с соперником. Второй игрок вводит этот код при подключении и попадает в ту же комнату. Важно понимать, что код можно использовать только один раз. Как только второй игрок подключился, комната становится активной, и попасть в неё по тому же коду уже невозможно. Игроки ходят строго по очереди: сначала первый, затем второй, потом снова первый, и так до финиша.

Если первый игрок достигает выхода, а второй всё ещё находится в лабиринте, партия не завершается автоматически. Второй игрок получает право сделать ещё один ход, что устраняет потенциальное преимущество первого и даёт шанс на ничью. Если после этого второй игрок тоже добирается до выхода, то объявляется ничья, если нет, то он проигрывает.

В случае, если какой-либо из игроков покинет комнату во время активной игры, он автоматически считается проигравшим. Далее запускается процесс обновления рейтинга, статистики и истории игры для обоих игроков.

### Локальный PvP с Codeboard

Дополнительная механика исключительно для локальных комнат: возможность опубликовать комнату на доске объявлений (Codeboard). После создания локальной комнаты создатель может выставить её на всеобщее обозрение и убрать в любой момент, пока комната находится в статусе ожидания. Другие игроки могут просматривать список опубликованных комнат в меню с их параметрами (размер, веса ветвления и коридоров) и подключаться к ним по указанному коду. Это удобно, когда вы хотите сыграть со случайным игроком, но сохранить контроль над настройками лабиринта или подключиться к игре, заранее зная об её параметрах. При подключении второго игрока комната автоматически снимается с доски. Публичные комнаты и одиночный режим не могут быть опубликованы.

### Публичный PvP

Режим для быстрого поиска случайного соперника. Игрок выбирает публичный тип комнаты и нажимает поиск. После этого система либо автоматически находит подходящего игрока, либо создаёт комнату с рандомными показателями размера (от 11 до 101) и весов. В публичном режиме игроки не могут зайти по коду комнаты и создать комнату самостоятельно. Соперник подбирается случайным образом из числа игроков, которые также ищут публичный матч.

Как только двое игроков оказываются в одной публичной комнате, матч начинается автоматически. Всё остальное работает так же, как в локальном PvP.

### Одиночный режим (Single Player)

Режим для тех, кто хочет пройти лабиринт в одиночку, без соперника. Игрок создаёт комнату с типом SP, после чего матч начинается сразу: не нужно ждать второго игрока. В одиночном режиме нет очереди ходов, игрок может двигаться по лабиринту в своём темпе. Цель та же: добраться до выхода. Как только игрок достигает выхода, лабиринт считается пройденным, и игра завершается.

Статистика прохождения не влияет на основной рейтинг Эло. Вместо этого в профиле игрока сохраняется отдельный счётчик пройденных лабиринтов в режиме одиночной игры. Если выйти из комнаты, то она удалится автоматически, никак не повлияв на статистику профиля.

### Дополнительные механики:

#### Чат

В игре есть встроенный чат. Он работает прямо во время матча и позволяет обсуждать ходы, шутить или просто поддерживать дружескую атмосферу. Интересно, что даже в одиночном режиме он есть, и предусмотрен скорее для временных записей.

#### Настройка комнаты

При создании локальной или одиночной комнаты игрок может настроить три ключевых параметра лабиринта:
- **Размер** — от 10 до 1000 (всегда нечётное число). Чем больше размер, тем сложнее и дольше прохождение.
- **Вес ветвления** — от 0 до 1. Определяет, насколько лабиринт будет разветвлённым. Высокое значение создаёт много развилок и тупиков.
- **Вес коридоров** — от 0 до 1. Влияет на длину прямых коридоров. Высокое значение делает лабиринт более вытянутым и предсказуемым.

Эти параметры делают каждую партию уникальной, позволяя адаптировать сложность под свой вкус или уровень подготовки. Интересно, что в публичной PvP интервал рандома размера комнаты от 11 до 101, что ускоряет случайные мачти и делает другие режимы более уникальными.

#### Система рейтинга

В игре реализованы две независимые системы рейтинга, каждая для своего режима. **PvP рейтинг** — классическая система Эло с K-фактором 50. Рейтинг изменяется в зависимости от результата матча и рейтинга соперника. Начальный PvP рейтинг — 150 очков. **SP рейтинг** — система рейтинга Садовского, основанная на сложности пройденного лабиринта и количестве завершённых одиночных игр. Чем сложнее лабиринт, тем больше очков получает игрок. С каждой новой пройденной игрой прирост немного снижается, что стимулирует проходить всё более сложные лабиринты. Начальный SP рейтинг — 0 очков.

#### Таблица лидеров

Для обоих типов рейтинга существует отдельная таблица лидеров. Игроки могут просматривать топ-10 по PvP рейтингу (Эло) или по SP рейтингу (Садовский). Таблица обновляется с периодичностью 1 час, что снижает нагрузку на базу данных при частых запросах. Это позволяет игрокам отслеживать свои успехи и сравнивать их с другими участниками, добавляя соревновательного духа даже для фанатов одиночного режима. Все профили игроков публично доступны для просмотра: можно изучить статистику, историю матчей и рейтинг любого игрока, что помогает оценить уровень соперника до или после встречи.

## История разработки

Это мой второй проект на Laravel, который изначально должен был стать первым, созданным к концу июня и являться рефакторингом процедурного [Labyrinth](https://github.com/AleksandrSadouski/Labyrinth). Но для изучения фреймворка я решил сделать проект с более простыми связями в БД и без синхронизации: [Dungeon-aas](https://github.com/AleksandrSadouski/Dungeon-aas). Но из-за того, что я недооценил сложность бизнес-логики, Dungeon-aas я делал дольше чем планировал, но он очень многому меня научил.

29 июля я приступил к полноценной работе над проектом Labyrinth-aas. Я не просто хотел перенести логику Labyrinth на архитектуру MVC, я хотел сделать полноценный апгрейд игры, сделав из прототипа полноценное API, что у меня в целом и получилось сделать. Отличия Labyrinth-aas от Labyrinth следующие:
1. Архитектура MVC
2. Статус код теперь не 200 в случае ошибок
3. Добавлена полноценная аутентификация
4. Добавлен профиль игрока и взаимодействие с ним (типичный CRUD с дополнением)
5. Статистика
6. Система рейтинга Эло
7. Таблица лидеров
8. Ничья как один из возможных результатов
9. Чат во время игры
10. Настройка лабиринта
11. История игр
12. Публичный тип комнаты
13. Одиночный режим
14. Система рейтинга Садовского
15. Система Codeboard

К 11 августа проект был в целом завершён, уже была регистрация, профиль, чат, но улучшения следуют и по сей день, особенно активно в 20-х числах того же месяца. Например, 23 августа появилась возможность просматривать чужие профили, менять пароль своего профиля и стереть данные профиля, а 24 августа была добавлена история матчей. 26 августа добавила новый режим публичной комнаты, 27 августа — уже одиночный. 28 августа появилась система Codeboard, а 29 — рейтинг Садовского. И конечно я рассказал лишь о самых заметных изменениях. 

Из сложностей проекта в основном были перенос логики с чистого PHP на Laravel, продумывание ничьи, распределение на сервисы, продумывания реализации режимов игры с архитектурной стороны и не только. К сожалению, на данный момент MazeService, как и в прошлом проекте, является сгенерированным ИИ.

## Установка Labyrinth-aas

Клонировать репозиторий:

```bash
git clone https://github.com/AleksandrSadouski/Labyrinth-aas.git
cd Labyrinth-aas
```

Установить зависимости:

```bash
composer install
```

Настроить окружение:

```bash
cp .env.example .env
```

В файле .env указать настройки базы данных:

```bash
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=labyrinth
DB_USERNAME=root
DB_PASSWORD=
```

Сгенерировать ключ и запустить миграции:

```bash
php artisan key:generate
php artisan migrate
```

Запустить сервер:

```bash
php artisan serve
```

Сервер будет доступен по адресу: http://127.0.0.1:8000
